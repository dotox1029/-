何を作ろうと思ったか
東武伊勢崎線と日本工業大学・宮代町運行バスの時刻表を組み合わせた通学ルート検索アプリ　　　
なぜ作ろうと思ったか
自分が通う日本工業大学は最寄り駅から約20分歩く必要があります。そのため、大学と宮代町がそれぞれ運行するバスを利用するのが最も効率的です。しかしこれらのバスはGoogleマップに掲載されていないため、バスに乗るには大学のホームページと宮代町の時刻表を別々に確認する手間がありました。この手間を解消するためにこのアプリを作成しました。　　　
生成AIとのやり取り
まず、バスの時刻データをテキストファイルで作成し、日本工業大学のバスを含めた通学アプリの作成を依頼しました。しかし生成されたのはバスの時刻表を羅列するだけのアプリで、意図とは異なるものでした。
そこで電車の時間も組み込むよう依頼し、乗車時間が2時間以内の駅を調べ、それぞれの時刻表をアプリに内蔵してもらいました。電車とバスの時間が連動し、タイムライン形式で表示されるようになりました。
動作確認として最寄り駅から大学までのルートを検索したところ、表示される時間が実際と大きくずれていることに気づきました。特急と普通電車の時間を区別できていないことが原因と仮定し修正を依頼しましたが、複数の駅で検証してもどれも正確な時間を表示できませんでした。
そのため、自力で主要駅の時刻表をテキストファイルにまとめて渡しました。それでもまだ誤差があったため、方針を切り替え、最寄り駅から完全に動作するものをゼロから作り直すことにしました。これまでに用意したバスデータと時刻表を渡して新たに作成してもらった結果、正確な時間でルートが表示されるようになりました。　　　
詰まったところとどう乗り越えたか
時刻表のデータをAIが正確に取得できていなかったため、自分で主要駅の時刻表を調べてテキストファイルとして用意し、直接渡すことで解決しました。
出力結果を検証したところ、電車の移動時間が特急と普通で区別されていないことに気づき、種別ごとに所要時間を分けて設定するよう修正を依頼しました。
しかし全駅分のデータを正確に揃えることが難しいと判断し、すべての駅に対応しようとする方針をやめ、自分が実際に使う路線と駅に絞って作り直すことで正常に動作するようになりました。　　　
次にやるなら何を変えるか
まず時刻表データを自動で取得・出力するツールを作成し、手動で時刻表を収集する作業を省力化します。その上で今回と同じ手順でアプリを構築することで、より効率よく開発できると考えています。また、対応する路線や駅を最初から明確に決めておくことで、データの不整合による手戻りを減らせると思います。
